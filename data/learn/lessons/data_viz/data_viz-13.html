What we mean by sequential data

Sequential data is any sort of data where the order has some meaning. For example, age groups. This guidance presents some colour options for using a sequential colour palette. However, it is important to note that a sequential colour palette should only be used when absolutely necessary. This is because the contrast ratios between the colours do not meet accessibility standards on their own and should be used alongside other options.

Choosing colours for sequential data

When you are presenting sequential data, it is best to use a single hue, or small set of closely related hues. You should change the lightness from pale to dark, rather than alternating between hues. You should keep the number of categories you require to a minimum and consider combining categories to reduce the number of colours needed. The more categories you use in a sequential colour palette, the less accessible the colours become, as there is less contrast ratio between neighbouring colours. Colours should also progress in the direction a user would expect.

Where 3 sequential colours are required, it is recommended to use the ‘dark blue’, ‘mid blue’, and ‘light blue’ as outlined in the palette table given in this guidance. An example of this might be a chart showing vaccine uptake with the sequential colours representing first dose, second dose, and third dose.

Where 4 sequential colours are required, it is recommended to use the ‘darkest blue’, ‘dark blue’, ‘mid blue’ and ‘light blue’. These colours give the most contrast against their neighbouring colours.

Where 5 sequential colours are required, the full set of blue colours shown in the palette table can be used. An example of this might be when using a map to show the difference in rates of a disease across areas split into 5 equal sized quintiles of geographies. The lightest blue would be used for those areas with the lowest rates, with areas with the highest rates being shown with the darkest blue.

A sixth colour, ‘pale grey’ is also shown in the palette table. This neutral grey can be used where you need to show areas that, for example, have no data or where you have suppressed the value. It is important to note that the colours have been chosen to work in monochrome, so the pale grey is lighter than the lightest blue in a monochrome view.

Information about these colours

These colours:

  • have been checked using a colour blindness simulator
  • have passed our checks for colour blindness
  • appear distinct across the types of colour blindness tested
  • appear distinct in greyscale

As this palette is restricted to tints of one colour it makes it difficult to get a sufficient colour contrast ratio across all the colours. This means that:

  • neither dark or light blue have a high enough contrast with the mid blue to meet the contrast ratio requirements
  • the darkest blue and dark blue do not have a high enough contrast ratio
  • the lightest blue and light blue do not have a high enough contrast ratio
  • the pale grey does not have a high enough contrast ratio with either the lightest blue or light blue
  • only the darkest, dark and mid blues have the required level of contrast with a white background

For this reason, you must provide an alternative accessible format when you use the sequential palette in a graphic. For example, this could mean supplying a downloadable data table alongside your graphic. As a result, we need to take care when using this colour palette in charts.

Using the sequential colour palette in charts

Due to the problems with contrast ratios in this palette our advice is as follows.

For all chart types

You should only use these palettes when it is absolutely necessary for the type of data you are presenting and there are no alternate methods.

Remember, provide a plain text version of all charts. This is even more important with this palette when you cannot meet the colour contrast requirements.

For line charts

You should:

  • label the lines instead of using a legend
  • consider using small multiple charts instead, if you need to show more than three lines

For clustered bar charts

You should:

  • make sure the order and orientation of bar chart legends match how categories are presented and state this above the chart, or label the bars in the first cluster directly
  • leave small gaps between the bars within clusters
  • give all bars a dark blue outline

Note: we only recommend outlining the bars when using this palette as bar outlines add unnecessary clutter. However, to use a sequential colour palette you must use a light colour for one of the bars. This is because the light colour does not have enough contrast with the white background. A border allows people to see the size of the bar even if they cannot see the colour fill. We outline all bars (instead of just the light blue bars) to maintain consistency.

For stacked bar charts

You should make sure the order and orientation of bar chart legends match how categories are presented and state this above the chart.

For maps

You should:

  • make sure the data is available in another format such as a downloadable data table
  • use alternative text or body text to draw out the main messages from the map (Figure 11 shows an example of this)

Note: maps provide a particular challenge for accessibility as colours are not presented in an order. This can make it difficult to match colours against a legend when there are insufficient contrast ratios between sequential colours. It is essential that data or messages from the data are communicated in an accessible way.

Using our colour palettes in Microsoft, R and Python

We have created guidance on how to implement all of our accessible colour palettes in Microsoft, R and Python.

R and Python colour palette packages

The Analysis Standards and Pipelines (ASAP) team have also created packages in Python and R for the colour palettes.

They are open source and available for anyone across government to use when creating data visualisations. It will be great for those working in DAP and they will eliminate the need for copy and pasting codes from the webpage.

For more information on how to install and use the packages, please read about afcharts, or py_af_colours documentation if you are using Python. There are also examples of how to use the afcharts colour palettes in the afcharts cookbook.
